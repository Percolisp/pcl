## HEAVY SLOTS (added s542; `~/pcl-agent-scratch/s513/heavy.sh`, its header is the reference)
Every gate / sweep / companion / board / everyday / A-B / ir-conform run goes through `heavy.sh LABEL leg|bench LOG CMD...`, started in the background; a log is a RESULT only if its last line is the `=== heavy.sh ... END rc=...` line.  A BOUNDED leg takes one of three slots (4G fence).  An EXCLUSIVE leg -- KIND `bench`, or a command or script that names `tools/run-perl-suite.pl`, `tools/bench-exec.pl` or `tools/t/install-container.t` -- takes the WHOLE box, and while it WAITS no bounded leg starts.  Therefore: (1) pass the script path itself as CMD (`heavy.sh L leg LOG /abs/SCRIPT`), and make it executable FIRST: `chmod +x SCRIPT && bash -n SCRIPT` before you queue it -- since s543 (#5191) `heavy.sh` refuses a non-executable script at once with exit 2, where the old one waited out the whole queue and then died of `Permission denied` (36 minutes, s543h); (2) **an exclusive leg holds ONE measurement** -- never everyday + a bench + the companion + mover re-runs chained (s539a held the box 52 minutes that way, s542); (3) only ONE exclusive leg is QUEUED on the box at a time: read `HEAVY.holder` and the tail of `HEAVY.queue` first; (4) a `--jobs 1` companion or board re-run is pass/fail work, not a timing: `HEAVY_BOUNDED=1 heavy.sh L leg LOG /abs/SCRIPT` gives it ONE slot although it names the companion runner (never for a timing, never for `--jobs` above 1); (5) a one-file run inside a leg takes `timeout 120`; a leg idle at load ~0 for five minutes is HUNG: kill it, mark its log VOID, diagnose; (6) **an exclusive TIMING leg is SHORT: TEN MINUTES at most** (added s543, 2026-11-22: s543h's bench leg held all four slots for 30 minutes with ONE core of sixteen busy -- three measurements chained against (2), and one row sized at 130 s a run, ten runs, for an answer of +1.0 % -- while two legs of s543i waited 45 minutes on an otherwise empty box).  Size a timing row so that ONE run takes a few seconds (the loop count is yours to choose; `t(N_big) - t(N_small)` needs seconds, not minutes); a first-run compile cost that takes over 30 s a run is measured ONCE per side, not best-of-N; write the expected duration in the leg script's header, and a measurement that cannot fit is split into legs with the queue released between them.  The companion's `--all` runs and the everyday run are exclusive for MEMORY, not for timing, and are as long as they are: queue one only when no other batch's bounded leg has waited more than ten minutes.  **(7) An exclusive leg is queued only when every RUNNING bounded leg is within about ten minutes of its end** (added s543, 23:46: an exclusive leg waits for all four slots and no new bounded leg starts while it waits -- s543j queued a three-minute timing leg five minutes after the round had started two 35-minute board chunks; it would have stalled every other leg on the box for half an hour, and the reviewing session killed the waiter).  Read `HEAVY.holder` for each holder's start time, and ask how long that KIND of leg runs (a board chunk ~35 minutes, a full gate 5-10, a sweep ~10, a wide A/B 12-30); a batch whose bounded leg runs longer than fifteen minutes writes its expected end into its STOP.md / status file so others can plan.  If you cannot tell, do the bounded work first and ask the reviewing session in an interim message.

## ORDINARY OR RARE (added s543, 2026-11-24; the USER's ruling -- `docs/supported-subset.md` sections 5 and 7)
Exit criterion 1 counts the open IN silent wrongs of ORDINARY code; a silent wrong of a RARE spelling is a known divergence, listed and not counted (`tools/task-triage.pl`, `--list in-silent-ordinary` / `in-silent-rare`).  Therefore: (1) **every task you file that is marked silent wrong carries `frequency` (`ordinary` | `rare`) and `frequency_reason`** (one line naming the EVIDENCE) beside `triage` + `triage_reason` -- `ordinary` = a working program meets it without its author doing anything unusual: you can NAME a program or module we hold that contains the shape (grep the board dists, `everyday/`, `lib/`, the Rosetta corpus `~/pcl-agent-scratch/s543/rosetta/corpus`) or a perldoc page that teaches the idiom; `rare` = an unusual spelling, an exotic variable, an experimental feature, a shape known only from a probe or from perl's own tests, or a case where perl itself dies or warns; if you cannot tell, write `ordinary` and say so in the reason (the number must not fall by omission); (2) **a neighbour your own probes find does not extend your batch unless it is ordinary**: a rare one is FILED with its reproducer and left -- you fix it only when you are already in its function and the fix is a few lines; (3) a brief's member whose tasks are all `rare` and that you have NOT begun is taken LAST, with a cap of ~15k tokens of reduction: past that, write the measurement into the task as `=== NOT TAKEN: rare (label) ===` and go on -- the ordinary members and the end-of-batch bars come first; (4) a probe table still reports every shape perl -> base -> tree, rare ones included: knowing a divergence is the point, fixing it is not always.
