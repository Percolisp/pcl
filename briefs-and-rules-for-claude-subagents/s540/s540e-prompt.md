1. **#4989 Storable `dclone`** (`lib/Storable.pm`): a deep copy does not NEED the serialised form -- real Storable's C code writes to memory and reads back because that is the code it has; the result is "a structure equal to the input sharing nothing with it".  **THE USER (s540): if it works, use the FASTEST implementation.**  So measure two candidates and ship the faster one that passes the differential probe: (a) the walk in the shim's Perl (the algorithm `lib/Clone.pm` has: a seen-table so shared and circular references stay shared, blessing kept -- s540b measured 3,000 copies 1.39 s -> 0.084 s through it; perl's XS 0.013 s); (b) ONE generic runtime primitive on the `builtin::` seam -- "deep copy of a value graph": hashes, arrays, scalar refs, refs to refs, the box model's number / string faces preserved exactly, blessing kept, identity of shared and circular referents kept by an `eq` table, an ITERATIVE walk (no stack death on a 10,000-deep structure) -- which the Clone shim then uses too (rule 11: one copier; rule 9a: the primitive is named for what it does and knows no module).  Whichever wins, it copies directly and falls back to freeze + thaw ONLY where the format path does something a plain copy does not: a class with `STORABLE_freeze` / `STORABLE_thaw` / `STORABLE_attach` hooks (the hooks MUST run, with their `$cloning` argument true), a CODE ref (dies "Can't store CODE items" unless `$Storable::Deparse` / `$Storable::Eval`), a GLOB, a tied container, a regexp object, anything the walker does not recognise (rule 12: an unknown referent kind takes the format path or dies as Storable does -- never a silent shallow copy).
