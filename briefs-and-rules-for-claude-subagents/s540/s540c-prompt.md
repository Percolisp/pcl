## MEMBER 1 -- #2006 PART 2: the collector closes what the program can no longer reach

### Why not a compile-time licence
A "returned-handle licence" (close `my $fh = f()` at the caller's scope exit) is UNSAFE: `f` may hand out a handle it also keeps (`$self->{fh}`, a cache), and the compiler cannot see that across a call.  Only the collector knows that NOTHING holds a handle.  So the design is run-time, and it is a BELT: it never closes a handle the program can still reach, and when the collector does not find a dead handle (SBCL's stack scan is conservative) the behaviour is exactly today's.

### Measure FIRST (each a ten-minute probe; write the answers into STOP.md before building)
1. Does PCL's handle object become garbage at all when the Perl variable dies -- what holds it (the `$.` table, the eof table `*p-eof-seen*`, the open-handles list the exit hook flushes, the fileno map, the DESTROY registry for a blessed `IO::File`)?  A strong table entry means the object is never collected: list every table that maps a handle or its stream, and say which are weak.  The exit-time flush of every open handle must keep working -- so the "all open streams" set must hold the STREAM without holding the HANDLE object, or hold it weakly and flush from the finalizer's own reference.
2. Which object carries the identity that dies with the last Perl reference: the glob, the box, the IO struct? ### Build (only what the measurements license)
* **The finalizer**: when the handle's identity object is collected, its stream is flushed and closed and its fd released -- for a handle that is still OPEN and that PCL opened (never STDIN / STDOUT / STDERR, never an fd PCL did not open, never one a live dup shares).  An implicit close: `$?` and `$!` untouched, a pipe's child reaped without publishing its status (the rule the scope-exit close already follows, ir-spec §6.5).  ONE close path: the finalizer calls what `%p-scope-close` calls (rule 11).
* **The triggers** (a collection is not free: it runs only where the program is about to fail or block without it):
  - `flock` WITHOUT `LOCK_NB` (and `LOCK_EX | LOCK_NB` / `LOCK_SH | LOCK_NB` that answer EWOULDBLOCK): try non-blocking first; on EWOULDBLOCK run a full collection + the pending finalizers, try once more; then do what the program asked (block, or answer false with `$!` EWOULDBLOCK).  A lock another PROCESS holds costs one wasted collection per blocking `flock`: measure it, and bound it (once per call, never in a loop).
  - `open` / `sysopen` / `opendir` / `pipe` / `socket` / `accept` / a piped open failing with EMFILE (or ENFILE): collect, run the finalizers, retry once.  The acceptance is #2006's own measurement: under `ulimit -n 1024`, 3,000 iterations of a loop that opens a lexical and PASSES it to a helper sub (the escaping shape; the non-escaping one is closed at scope exit already) must complete.
* **Do not** add a periodic collection, a handle count threshold, or a finalizer on every scalar box.  Do not close a handle at a caller's scope exit by analysis (see "Why not").
* Rule 12: a failure inside the finalizer (EBADF on an fd something else closed) is announced on stderr once and never signals in the finalizer's thread.
