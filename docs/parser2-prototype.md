# Parser2 — the v2 pipeline prototype (structured emission)

**Written:** 2026-07-02
**Status:** working prototype, opt-in via `PCL_V2=1`; v1 untouched
**Spec it implements a slice of:** `docs/codegen-rewrite-spec.md` (R3 +
items #1/#2/#3 + a first cut of Phase-4 unboxing), reviewed in
`docs/codegen-rewrite-review.md`.

## Switch

```bash
./pl2cl < prog.pl              # v1 (unchanged, default)
PCL_V2=1 ./pl2cl < prog.pl     # v2 prototype
PCL_V2=1 ./runpl prog.pl       # runs through the same env switch
```

Same external API: `Pl::Parser2->parse_file/parse_code/parse` return the same
CL-text-with-`(in-package :pcl)`-marker contract as `Pl::Parser`, so pl2cl's
preamble injection and every caller work unchanged.

## The objects

| File | Object | Role |
|---|---|---|
| `Pl/CLForm.pm` | forms (`[head, @args]`, `['list',…]`, `raw($cl)`) + printer | The ONLY place text is produced. Parens balance and indentation encodes depth **by construction**; nothing downstream ever re-parses emitted text. `raw()` embeds output of the *original* generator opaquely. |
| `Pl/Parser2.pm` | statement-level lowering | `my` declarations nest the rest of their block inside a `let` **form** (scoping is tree structure, not emit-order bookkeeping — kills the `_pending_let_closes`/paren-archaeology class from `intra-sub-goto-plan.md`). Subs, if/unless/while/until/foreach, return, statement modifiers. |
| `Pl/ExprToCL2.pm` | expression lowering, STRICT native subset | Same API as `Pl::ExprToCL` over the same PExpr/OpcodeTree. Handles scalars, decimal numbers, binary arith/comparison, parens — all-or-nothing per expression, `undef` otherwise. |
| `Pl/VarAnnotator.pm` | Gate-1 prototype | Conservative "may this `my` scalar leave the box?" — unboxable only when declared once, never ref-taken/`local`/`pos`/`m//g`-target/++-ed/compound-assigned/closure-referenced, no string `eval` in region, and *every* write is arithmetic-shaped (so raw slots only ever hold raw numbers, never a box that could alias). Any doubt → boxed → byte-equivalent semantics. |

## The fallback seam (how v1 and v2 coexist)

Every expression is first offered to `ExprToCL2`; anything outside the native
subset is generated by a real embedded `Pl::Parser` instance
(`fallback_parser->_parse_expression` → PExpr + ExprToCL unchanged) and lands
in the form tree as a `raw` leaf. So v2 grows **one node type at a time**
while all of Perl keeps working through the original machinery. Two
legacy-boundary rules worth knowing:

- fallback strings get the same `(p-scalar-= $x` → `(p-my-= $x` conversion
  the old `_emit` does (v1 does this rewrite inside `_emit`, which the
  fallback path bypasses); v2-native assignments never need it — they are
  lowered directly as `p-my-=`/`setf` forms;
- `fallback_parser->{_let_bound_vars}` is kept up to date as Parser2 opens
  scopes, so the original generator makes the right my-vs-package calls.

## What the output already shows (pinned by `Pl/t/parser2-01.t`)

- spec **#3**: `sub f { my ($a,$b) = @_; … }` → `(&optional ($a (p-undef))
  ($b (p-undef)) &rest %_args)` — no `p-list-=`, `f()`/`f(1)`/`f(1,2,3)` all
  legal;
- spec **#1**: no dead hoisted boxes; `my $c = $a + $b` binds `$c` **raw at
  its declaration site**;
- spec **#2**: no `(let ((*wantarray* :void)) …)` wraps; plain copies are
  bare `(p-my-= $a $b)`;
- Phase-4 first cut: `my $sum = 0; $sum = $sum + …` → `(let (($sum 0))` +
  `(setf $sum (p-+ …))`;
- **native funcalls + R2 caller half** (added same day): a pre-pass records
  per-sub `{ cl_name, insensitive }`; calls to known subs with native args
  compile to direct `(pl-f …)`, and the `(let ((*wantarray* nil)) …)` bind is
  emitted **only when the callee can observe context** (`wantarray` in body,
  or any return value not scalar-rooted — where scalar-rooted = the return
  expression's tree root is an arith/comparison/`.` operator, a `$scalar`, a
  number, or a string literal; `&&`/`||`/`//`/`x` roots and funcall roots
  propagate context, so they stay sensitive, as do bare `return;` and
  compound tails).  Recursive fib becomes
  `(p-+ (pl-fib (p-- $n 1)) (pl-fib (p-- $n 2)))` — direct calls, no binds;
- verified end-to-end: fib (recursive + loop), intmath, and the
  sensitive/insensitive mix produce perl-identical output under the runtime.

Measured effect of the funcall step (fib(29), startup excluded): v1 ≈ 0.72 s
→ v2 ≈ 0.51 s compute (~30% on call-bound code) vs perl 0.141 s. The
remaining gap is `p-sub`'s five per-call special bindings + `p-flatten-args`
+ generic `p-+`/`p-<` — R1 and the p-sub leaning, not the caller side.

Speed note: correctness shapes only — the prototype's intmath is barely
faster than v1 yet, because `p-+`/`p-foreach` still carry the Tax-3/Tax-2
costs (`docs/where-the-time-goes.md`). The unboxed shapes start paying the
moment R1 (inline fast-path ops + FPU-modes-at-startup) lands in the runtime.

## Prototype boundaries (deliberate)

Unsupported statement kinds `die "Parser2 TODO: …"` (packages, C-style for,
elsif chains, modules/`use`, non-scalar `my`, string-eval interplay is
conservatively boxed). The v1 pipeline is bit-for-bit unaffected —
`PCL_V2` only switches which class pl2cl instantiates.

## Next steps, in leverage order

1. **R1 in the runtime** (next session, user-confirmed): FPU modes at
   startup + delete `%pcl-ieee-arith`; inline numberp-guarded fast paths on
   `p-+`/`p-<`/…; Tier-3 declaims. Independent of Parser2; makes the unboxed
   shapes and direct calls actually fast.
2. Lean `p-sub`: the five per-call special bindings (caller-pkg/subname
   stacks, depth, caller-wantarray) are the next call-cost after the caller
   bind — bind lazily or only for subs that need caller()/wantarray.
3. Grow `ExprToCL2` native set: string concat/interpolation; let
   VarAnnotator's `_arith_rhs` accept known-insensitive funcalls so
   `my $x = f() + 1` can unbox.
4. Statement kinds: elsif, C-style for (`p-for` form), package, `use`.
5. Replace VarAnnotator's text-scan gates with the OpcodeTree walk
   (`type-flow-and-codegen-plan.md` §(s)) once shapes stabilize.
