# Pack/Unpack Rewrite Plan

## Problem

`cl/pcl-pack.lisp` is broken (session 179 left a duplicate top-level form).
The root cause is that p-pack (~261 lines) and p-unpack (~370 lines) were written
as single monolithic deeply-nested functions in session 178, violating the 80-line
rule. Patching them has repeatedly introduced new structural bugs.

## Approach: Write in Perl, Translate via PCL

Write the implementation in Perl first. Test it against `perl-tests/pack.t` directly
(run with `perl`). Once the Perl is correct, translate with `./pl2cl`. No manual CL
writing, no paren counting.

**Float handling seam:** IEEE 754 bit manipulation requires SBCL-specific functions
(`sb-kernel:make-single-float` etc.) that have no clean Perl equivalent. Handle this
with two stub Perl subs:

```perl
# Stubs — bodies replaced with real CL after translation
sub _pack_float32   { my ($val)       = @_; "" }          # returns 4-byte string
sub _pack_float64   { my ($val)       = @_; "" }          # returns 8-byte string
sub _unpack_float32 { my ($s, $i, $be) = @_; 0.0 }       # returns float
sub _unpack_float64 { my ($s, $i, $be) = @_; 0.0 }       # returns float
```

After `./pl2cl pack-impl.pl > cl/pcl-pack.lisp`, replace just those four generated
function bodies with the real CL:

```lisp
;; _pack_float32 body — replace generated stub with:
(let* ((bits (sb-kernel:single-float-bits (float val 1.0s0)))
       (be   (or force-be (not force-le))))
  (if be
      (map 'string #'code-char
           (list (ldb (byte 8 24) bits) (ldb (byte 8 16) bits)
                 (ldb (byte 8 8)  bits) (ldb (byte 8 0)  bits)))
      (map 'string #'code-char
           (list (ldb (byte 8 0)  bits) (ldb (byte 8 8)  bits)
                 (ldb (byte 8 16) bits) (ldb (byte 8 24) bits)))))
```

That is the only manual CL editing required. Everything else comes from translation.

## Perl Implementation Structure

```
cl/pack-impl.pl          — the Perl source (keep this file)
cl/pcl-pack.lisp         — generated by ./pl2cl, with float stubs replaced
```

Keeping `pack-impl.pl` means: when a bug is found, fix the Perl, re-translate,
re-apply the float stubs. No manual CL debugging.

### Perl function breakdown

```perl
sub _pack_next_directive { }  # parse ch + modifiers + count from template string
                               # returns (ch, bang, force_be, force_le, all_p, count, new_ti,
                               #          grp_inner_or_undef)

sub _pack_integers  { }  # c/C/s/S/l/L/q/Q/n/N/v/V/j/J/i/I  → byte string
sub _pack_floats    { }  # f/d/F/e/g  → calls _pack_float32 / _pack_float64 stubs
sub _pack_strings   { }  # a/A/Z/b/B/h/H/u  → byte string
sub _pack_ber       { }  # w  → BER-encoded byte string
sub _pack_slash     { }  # ch/DATA_FMT  → byte string

sub _unpack_integers { }  # c/C/... → list of values, new si
sub _unpack_floats   { }  # f/d/F   → calls _unpack_float32 / _unpack_float64 stubs
sub _unpack_strings  { }  # a/A/Z/b/B/h/H/u/U  → list of values, new si
sub _unpack_ber      { }  # w  → list of values, new si
sub _unpack_slash    { }  # ch/DATA_FMT  → list of values, new si

sub p_pack   { }  # top level: parse template, dispatch, return string
sub p_unpack { }  # top level: parse template, dispatch, return list
```

Each sub ≤ 60 lines. `_pack_next_directive` is shared by both sides.


Or simpler: add a small test harness at the bottom of `pack-impl.pl` that exercises
a representative sample. Get the Perl passing before translating.

## Translation and Post-Processing

```bash

# Then manually replace the four float stub bodies (< 10 lines each)
# Run paren checker

```
